## Delivered scope

Outgoing task-question answers now persist an immutable company/job/thread/question/content-bound intent and one return-wait ID atomically. Changed content is refused; exact explicit retries reuse the original pending live wait and stored JSON without extending its deadline. The Matrix account, room, peer and root are bound. Transport failures retain the wait and record SEND_UNCONFIRMED evidence, because a result may still arrive. A fresh assistant can recover the prepared answer from escaped, current-job context.

Forward-only t024 adds forced tenant RLS, composite tenant/job/thread/wait foreign keys, unique identities, explicit least-privilege grants and mutation protection. Newly opened threads explicitly opt into protocol 1. All historical threads remain protocol 0 and answering them fails closed; no old content, wait ownership or delivery is inferred. An existing unbound outbound key is also refused. See ADR-0031 for options, trade-offs and rollout.

This is explicit local retry recovery, not a general durable transport queue or exactly-once certification. Concurrent exact attempts may reach Matrix with the same transaction key; no new single-sender lease or automatic replay worker exists. In-flight messages cannot be unsent after cancellation. Borrowed-call result sends and other ingress are separate. No shipping manifest, business/provider capability or source-parity change. All eighteen remain incomplete.

## Migration, privacy and handoff limits

Production rollout requires DBA review of t024 and its index/lock footprint on a recent restore, plus an explicit owner-approved plan for existing protocol-0 threads. Do not bulk-promote them or guess content from outbound event IDs. Drain old answer senders and assistant sessions; old binaries can bypass the new protocol. Refresh matching backend/assistant artifacts, preserving v2 expected-ID, question/result-receiver and t023/input-expiry-worker coordination. Mixed-version rolling compatibility is not certified.

Intents duplicate answer content and may contain personal data. The SQL comment flags it; subject discovery, manifest tagging, retention, export and erasure semantics remain unimplemented/review-required. Generic nulling/deletion would break replay integrity and is deliberately not permitted. Matrix token/endpoint rotation, retention/replay windows and real homeserver deduplication are not certified by this fixture.

Owner decisions are still needed on eligible/elevated approver roles, amount/currency limits, self-approval and historical/nonhuman handling. Complete workflows, providers, source parity, privacy/legacy conversion, production restore/DBA approval and real Matrix/model/NEOS UI acceptance remain open.
